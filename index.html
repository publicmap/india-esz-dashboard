Edit data

This dashboard is built by joining the MoEFCC ESZ notification list against protected area records on Wikidata, which supplies each protected area's coordinates, type, and other reference details. Because the join relies on matching names and states across two sources, some records end up missing a coordinate or unmatched entirely. The lists below track those gaps — each links to where the underlying data can be corrected, either directly on Wikidata or via a pull request to this repository.

QA: protected areas not yet matched to Wikidata (–)

This combines both sides of the join that couldn't be matched to each other: protected area names/states from MoEF ESZ notifications ( shaded rows) with no corresponding Wikidata item, and Wikidata items ( shaded rows) with no corresponding MoEF notification — usually a spelling variant, a notification covering multiple parks, or an item genuinely missing on one side. The list is sorted by state then name so a MoEF/Wikidata pair for the same place tends to land next to each other.

Match mode: click Copy name on a Wikidata row, then Paste match on the MoEF row it corresponds to. Each match adds an "add alias" QuickStatements line below (so the MoEF name becomes a matchable alias on that Wikidata item) — run the batch at quickstatements.toolforge.org, then also add a row to data/corrections.csv so this dashboard's own join picks it up before the next Wikidata dump. Create mode: tick the MoEF rows that genuinely have no Wikidata item yet to build a QuickStatements batch that creates one per row (location/P131 isn't guessed — add it manually after creation).

Protected areas without a Wikidata coordinate (–)
